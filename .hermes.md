# Deterministic Writing Runtime — Hermes Project Contract

This repository is a deterministic fiction-control workspace. The model may propose plans and prose; Python owns canon, narrative state, validation, retry budgets, disclosure isolation, acceptance, and salvage.

## Hard rules

1. For an end-to-end writing request, Hermes should operate the project conversationally but delegate the actual recursive writing loop to `integrations/hermes/pilot_controller.py`.
2. Interactive Hermes is the operator, not the planner/writer/controller. Do not manually recreate plan -> draft -> critique -> rewrite in the current chat.
3. Never bypass a non-zero gate result by declaring the text acceptable yourself.
4. Never copy raw analyzer messages into a model prompt. Use prompts emitted by the runtime.
5. Never resume a model context across disclosure epochs. The pilot controller uses fresh child Hermes calls for generative phases.
6. Treat `canon_source/` and `state_source/` as editable source; compiled SQLite is runtime authority.
7. Never mutate accepted prose from an unvalidated model response. Apply through runtime contracts/reassembly.
8. If a workflow reaches `human_review`, stop. Do not create another unbounded critique/rewrite loop.

## Conversational pilot UX

The user should be able to say "start a writing pilot", provide a chapter brief, or ask to continue/rewrite a chapter without manually typing runtime commands.

For a pilot request:

- save the user's brief faithfully under `runtime_state/operator/` or the selected pilot work directory;
- determine `plan-id`, `chapter-key`, `at`, `timeline_branch`, and `viewpoint` from the user's request/project context;
- invoke `integrations/hermes/pilot_controller.py` once;
- report the deterministic controller result and artifact paths;
- do not inspect hidden author-scope planning packets merely to narrate progress.

When the user explicitly asks for the current/example/first pilot fixture, use `book1/ch05`, branch `main`, viewpoint `Mara`, plan id `pilot.first.ch05`, workdir `runtime_state/pilot-first`.

## Interactive start

For interactive Hermes use, launch through `integrations/hermes/start-project.ps1` (Windows) or `start-project.sh`. This pins the working directory and preloads the skill.

The current interactive session may remain conversational while the controller launches fresh child Hermes processes for planning, disclosure epochs, and repair. Fresh process boundaries—not role names—provide disclosure isolation.

## Temporal v0.7 rule

Treat `timeline_branch` as part of every planning/drafting/repair contract. Never assume `main` after a chronobreak. Do not carry facts/state from a parent after the branch fork unless the deterministic runtime re-injects them. Use the runtime's `state-diff`/canon surfaces rather than memory when branches disagree.
