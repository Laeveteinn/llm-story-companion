# Deterministic Writing Runtime — Hermes Project Contract

This repository is a deterministic fiction-control workspace. The model may propose plans and prose; Python owns canon, narrative state, validation, retry budgets, disclosure isolation, acceptance, and salvage.

## Hard rules

1. For fiction planning, drafting, continuity changes, canon-sensitive rewrites, or repair, invoke `python write_runtime.py ...` rather than improvising an unvalidated workflow.
2. Never bypass a non-zero gate result by declaring the text acceptable yourself.
3. Never copy raw analyzer messages into a model prompt. Use prompts emitted by the runtime.
4. Never resume a model context across disclosure epochs. Use the fresh-call integration for automated generation.
5. Treat `canon_source/` and `state_source/` as editable source; compiled SQLite is runtime authority.
6. Never mutate accepted prose from an unvalidated model response. Apply through runtime contracts/reassembly.
7. If a workflow reaches `human_review`, stop. Do not create another unbounded critique/rewrite loop.

## Interactive start

For interactive Hermes use, launch through `integrations/hermes/start-project.ps1` (Windows) or `start-project.sh`. This pins the working directory and preloads the skill.

For strong automation/fresh-context isolation, use `integrations/hermes/hermes_fresh_call.py`; do not ask the current interactive session to pretend it forgot prior author-only information.

## Temporal v0.7 rule

Treat `timeline_branch` as part of every planning/drafting/repair contract. Never assume `main` after a chronobreak. Do not carry facts/state from a parent after the branch fork unless the deterministic runtime re-injects them. Use the runtime's `state-diff`/canon surfaces rather than memory when branches disagree.
