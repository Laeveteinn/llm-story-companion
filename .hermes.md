# Deterministic Writing Runtime — Hermes Project Contract

This repository is a deterministic fiction-control workspace. Models propose plans/prose; Python owns canon, narrative state, chronology, disclosure, model routing, retry budgets, repair routing, and acceptance.

## Hard rules

1. For a named story, use `writing-project-init`, `writing-project-model`, and managed `writing-pilot --project <slug>`. Do not guess alternate module names or call `pilot_controller.py` directly.
2. Interactive Hermes is the operator only. Never manually recreate plan -> draft -> critique -> rewrite.
3. Normal writing mode must not modify tracked harness source, tests, skills, root fixtures, or tracked configuration. A pilot failure is not permission to patch the harness.
4. Named projects require an explicit provider/model pin. Never inherit Hermes Desktop's last-used/default model.
5. `writing-pilot --project <slug>` is non-blocking. Poll with `--status`; if it is already running, do not launch another copy. Use `--cancel` only when the user requests a stop.
6. Treat `failed`, `orphaned`, `harness_modified`, `blocked_harness_dirty`, and `human_review` as terminal for the current writing operation. Report and stop.
7. Never bypass a non-zero deterministic gate or convert it into conversational approval.
8. Never resume model context across disclosure epochs or copy raw analyzer messages into repair prompts.
9. Never use destructive project replacement unless the user explicitly says to discard/restart that project; replacement requires `--replace-existing <exact-slug>`.

## New user-owned story

The Mara/Sable Bind stores are fixtures only. Save the user's premise faithfully, initialize a sparse `projects/<slug>/` namespace, then pin the exact provider/model. Character POVs use `--viewpoint-kind character`; omniscient/general-third/no central POV uses `--viewpoint-kind narrator` rather than creating a fake character.

`projects/` is ignored by the public harness repository by default.

## Managed-run safety

A managed run requires tracked Git files to be clean. It records the current Git HEAD and the controller checks that tracked source remains unchanged between deterministic/model phases and before acceptance. If source changes, the result is untrusted and the run aborts.

A project brief under `projects/` may not silently use root fixture canon/state defaults. The named-project operator supplies the correct project-specific authority paths.

## Temporal rule

Treat `timeline_branch` as part of every planning/drafting/repair contract. Never assume `main` after a chronobreak or carry abandoned parent-future state unless the deterministic runtime explicitly reintroduces it.
